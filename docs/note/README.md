## 貼るまえに直すところ

1行目のタイトルにある `#◯` が、連載番号のままです。ここだけは貼る前に入れてください。
ほかに手を入れないと出せないところはありません。

## note に貼る手順

1. 1行目の `# 教室で使えるかもしれないもの作り #◯ ...` から `#` を外し、タイトル欄に貼る。
2. `##` の見出しから最後のハッシュタグまでを、本文欄に貼る。
3. 画像は `images/` から手で上げる。本文中の `![...](images/xx.png)` の行が、上げる位置と順番です。
4. 画像の直後にある短い一行は、キャプション欄に移す。本文には残さない。
5. いちばん下のタグの一行は、note のハッシュタグ欄に入れる。16個あります。
6. 見出しの言葉は変えない。giga-school.com の紹介ページが、この並びから目次と検索の索引を作っています。

## 取材メモ

一度目の原稿は「実物のつぼみが手に入らない季節を補うため」という前提で書いていました。
取材でそこが違うと分かったので、記事の背骨をまるごと書き直しています。

### 聞き取った内容

- このアプリは、花のつぼみを実際に見てわからないときのために作ったものではない
- 光村図書の国語で、1年生が初めて説明文を学習するのが「つぼみ」という教材。
  以前は「くちばし」だったところが、最新の教科書で入れかわった
- この教材で学ぶのは、説明文には 問い の文と 問い の答えがあるということ
- 単元の終わりに、学習した文の関係を使って、つぼみと花の文を書く
- そのとき、図書室にある学習用の図書に教科書と同じ文型で書かれたものがあり、
  そこから選んで文を書く
- ただ、本が好きなときに使えないことや、友達と取り合いになることがある。
  それをなくすためにアプリを作った
- アプリにすることで、つぼみから花が咲くような体験をカードの上で行える
- 文章を読むのが苦手な1年生のこの時期に、音声で文章が聞けるところもよい部分だと考えている

### 教科書からの引用について

記事に引いた教科書の文は「これは、なんの つぼみでしょう。」と
「これは、あさがおの つぼみです。」の二つだけです。どちらも文型そのもので、
とい と こたえ の関係を説明するために要る最小限にとどめました。
つぼみの形をせつめいしている文は、引かずに言いかえてあります。
それでも気になるようなら、あさがおの一文は「これは、なになにの つぼみです。」に
置きかえられます。意味は通ります。

## 1枚目の画像が紹介ページから読めるか

このリポジトリは Vite で `dist/` だけを配っているので、`docs/note/images/` は配信物に入りません。
そのままだと、紹介ページの SNS カード画像がサイト共通の絵に落ちます。

対処として、1枚目だけを配信物に入れてあります。

    public/docs/note/images/01-home.png   横1200ピクセル、592KB

`npm run build` すると `dist/docs/note/images/01-home.png` に入るので、公開後は
`https://tsubomi-learning.giga-school.com/docs/note/images/01-home.png` で読めるようになります。

確認は、公開の翌朝に次のコマンドでお願いします。撮影した環境からは
giga-school.com へ出られなかったため、こちらでは確かめられていません。

    curl -sI https://tsubomi-learning.giga-school.com/docs/note/images/01-home.png | head -1

200 が返らないときは、`public/docs/note/images/` の置き場所を見直してください。
2枚目より先は `raw.githubusercontent.com` から読まれるので、そのままで構いません。

## 撮影のときに気づいたこと

記事には書いていませんが、公開の前に見ておいてほしいところが三つあります。

一つ目。`public/privacy.html` と `public/terms.html` が、本体の画面のどこからもリンクされていません。
URL を直接打たないと開けない状態です。記事では URL を直に載せてしのぎましたが、
フッターにリンクを一本足すほうがよいと思います。

二つ目。`public/privacy.html` の中身が、このアプリに当てはまらない項目を含んでいます。
Google アカウントへのログイン、生成AIへの送信、ブラウザのローカルへの保存。
どれもこのアプリはしていません。ほかのアプリと共通のひな型を使っているためだと思いますが、
学校に見せると、していないことをしていると読まれます。このアプリ用に削る修正を、
記事とは別に出すことを勧めます。

三つ目。読み上げ中にボタンが「とめる」に変わるところは、写真に撮れていません。
撮影に使ったブラウザに日本語の音声が入っておらず、読み上げが始まらなかったためです。
コードの上では読み上げの開始で切り替わることを確認しています。実機で一度見てください。

このほか、画面のエラーは1件も出ていません。20枚のカードは全部めくれました。

## 撮り直すときの手順

    npm i --no-save playwright peer
    npm run build
    node <skill>/scripts/serve.mjs dist 4180 /
    node <skill>/scripts/capture.mjs .tmp-shots/shots.mjs \
      --base http://127.0.0.1:4180/ --out docs/note/images --strict

撮影用のシナリオ `.tmp-shots/` は納品時に消してあります。書き直すときは次の4つに気をつけてください。

Google Fonts に出られない環境では、書体が端末のものに落ちて本番と見えかたが変わります。
Kosugi Maru と Outfit を端末に入れたうえで、`page.route` で
`https://fonts.googleapis.com/**` を空のスタイルシートで返すと、本番と同じ絵になります。

画像に `loading="lazy"` が付いているので、そのまま撮ろうとすると画面が止まったと判定されて進みません。
撮る前に全部の `img` を `eager` にして、読み終わるまで待ってください。

カードをめくったあとはマウスを画面の外に逃がしてください。押した場所に残したままだと、
影が濃くなって拡大した状態が写ります。

撮ったあとは横1800ピクセルまで縮めています。2倍のまま出すと1枚が3MBを超えます。
